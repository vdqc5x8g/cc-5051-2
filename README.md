# 升降通路 · 时间相关导航原型

轨道站检修角色的三维导航原型。楼层之间只有 **按周期到站的升降平台** 和 **定时开启的闸门**，
角色必须同时规划 **步行、等待、搭乘**，并在三维场景中真实执行。

边代价依赖 **预计到达时刻**：规划器不会用“固定距离最短路线”替代“最早可达路线”。
等待位置永远位于安全可站区域（边缘线之后）；平台不在本层时不会跨越空隙。

## 启动

```bash
npm install
npm run dev            # http://localhost:5173
```

生产构建：

```bash
npm run build && npm run preview
```

需要支持 WebGL 的浏览器。页面加载后自动生成首条计划，按 **播放** 驱动内核时钟。

## 界面怎么用

| 区域 | 作用 |
| --- | --- |
| 顶部 | 播放 / 暂停、+1s 单步、倍速（0.5×–8×）、内核时刻、重置 |
| 行程设置 | 出发层、目的层、出发时刻；“刚错过班次”把出发时刻拨到最近一班发车之后 |
| 班次调整 | 编辑每台平台的停站时长、层间速度、开门延时、相位；改动立即写回内核并重算 |
| 电梯服务状态 | 逐层关闭服务；失败会回升降通路内核，结果区显示不可达原因与恢复时刻 |
| 验收场景 | 一键载入四组验收用例 |
| 导航结果 | 计划到达、搭乘动作、等待合计、固定距离法、穷举参考、逐步时间线与条件 |
| 当前日程 | 未来 3 分钟的到站 / 开门区间 / 闭锁原因 |
| 诊断 | 内核时刻、平台位姿、搜索展开量、错过班次原因 |

三维场景：拖拽旋转、滚轮缩放。青色/琥珀色平台随内核位姿升降，闸门只在平台停靠且开门区间内抬起；
蓝色管道是最早可达路线，橙色虚线是固定距离法的对照路线；角色脚下的光环颜色表示
安全站立 / 等待 / 搭乘。

## 同一个状态来源

`src/core/timetable.js` 是唯一的升降通路内核：

- `buildLiftPlan(lift)`：由停站表生成闭环时间表（到站、发车、开/关门区间、腿时长）。
- `liftPose(plan, t)`：平台在时刻 `t` 的位姿（停站时严格贴层，运动时平滑升降）。
- `doorState(plan, closures, deck, t)`：某层车门是否开启，附带原因。
- `liftStopEvents(...)` / `closureAt(...)`：服务状态叠加后的到站事件。

规划（`src/core/planner.js`）与渲染/动画（`src/scene/StationScene.js` + `src/core/follower.js`）
读取同一份 `t`。**不存在“先让动画到达、再补一条时间线”的路径**：角色的每一帧位置都是
`(plan, kernel time)` 的纯函数；到站、开门、登乘、离车都由同一个 `t` 求值。

跟随器（`Follower`）在进入每一步之前用 **实际条件** 确认：

- `approach`：平台在本层且车门已开，否则不越过空隙并重算；
- `ride`：发车前一刻平台确实停靠本层；
- `alight`：到站后车门确实开启；
- 跨越空隙/离车期间持续校验，状态变化立即停下并重算；
- 在车内时收到班次/服务变更，会挂起并在到站后重算。

## 模型要点

- 安全可站节点：`center`、`holdA`、`holdB`（等候区在边缘线之后 1.0 m）。
- 平台停站表：A `L0→L1→L3`，B `L0→L2→L3`（闭环周期）。
- 状态 = `(层, 安全节点)`；标签 = 最早到达时刻。等待始终允许，因此最早标签可支配较晚标签。
- 登乘截止 = 关门 − `BOARD_BUFFER`；离开截止 = 关门 − `ALIGHT_BUFFER`。
- 服务闭锁 `{liftId?, decks, from, to, reason}` 会从事件与门状态中同时扣除。

## 测试与验证

```bash
npm test               # 21 个内核/跟随器测试
```

覆盖：闭环时间表、位姿连续与停站稳定、门只在停站且开门区间开启、错过班次顺延、
固定距离法劣于最早可达、服务闭锁切换平台、目的层不可达、与可枚举小图参考逐时刻对比、
搭乘期间角色位姿逐帧等于内核位姿、车内挂起重算等。

浏览器验收脚本（需要 Chromium）：

```bash
npx playwright install chromium
node test/ui.smoke.mjs
node test/ui.verify.mjs    # 等待原因、搭乘位姿一致、到达偏差、控件写回内核、四组场景
```

`ui.verify.mjs` 会输出 JSON 断言数据，并截图到 `/tmp`。

## 目录

```
src/core/station.js      几何、安全节点、行走时间
src/core/timetable.js    升降通路内核（唯一状态源）
src/core/planner.js      时间相关最早到达搜索 + 固定距离基线 + 穷举参考
src/core/follower.js     执行跟随器（逐边界条件确认、重算、实际偏差）
src/scene/StationScene.js 三维场景（只消费内核帧）
src/ui/                  界面与控件
test/                    vitest + Playwright 验收
```
